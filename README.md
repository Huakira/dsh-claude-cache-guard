# DSH Claude Cache Guard

个人自用插件，代码和文档由 AI 辅助编写。适合在 DSH 中使用 Claude 长会话、需要避免插件变更后无提示地重建历史缓存的用户。

安装：`dsh plugin --profile web add @huakirax/dsh-claude-cache-guard`。本插件针对 DSH `0.2.2-rc.1` 的公开服务接口开发；变更线上依赖前应等待宿主任务空闲。

## 工作方式

平时监听工具注册与移除、系统提示注册、插件管理操作和热重载。额外监听当前 profile 的 manifest、patch 文件，也可配置其他文件。连续通知会合并，实际变更后才核对会话的工具定义、顺序及固定系统指令。

正常请求只读取待处理状态，不重新计算指纹或扫描历史。新会话首次建立 Claude 请求基准，已卸载会话恢复时核对一次；宿主重新启动后也会核对已持久化的基准。

确有变化时，该会话下一次 Claude 请求被暂停。被取出的用户消息以相同 ID 和顺序保留在宿主的持久 inbox 中，附件也保留。插件不把提醒插入模型上下文，也不替已卸载的工具保留虚假定义。拦截后在输入区用 error 级通知和常驻文案说明原因；连续回合不会因为上一次状态读取未完成而丢掉提示。

- `/cacheguard`：查看当前会话状态。
- `/cacheaccept`：明确接受当前定义变化可能带来的缓存重建。只更新接受记录，不自动调用模型。
- 接受后发送“继续”，处理保留的消息；无需重发原文，避免重复排队。

Web 输入区有“缓存保护”状态按钮；打开会话以及每个回合结束时读取一次轻量服务端状态，只有需要处理的变更才自动以 error 通知并显示常驻说明，支持“接受本次变更”。这是界面的状态读取，不是重新核对指纹，也不执行模型请求；没有定时轮询。没有 Web 客户端时可直接使用上述命令。系统指令指纹比较的是正文：会话里的 content 块和 `renderPrompt` 字符串视为同一份；旧版把数组整段哈希、核对时却哈希字符串，会造成“固定系统指令变化”误报。

纯样式变更即使产生配置通知，只要实际工具和固定指令相同，就不会拦截。变更撤回、定义恢复原状时，也会解除待处理状态。接受只针对本次定义，下一次新变更仍会保护。

## 配置

```yaml
- insert:
    - id: claude-cache-guard
      name: dsh-claude-cache-guard
      providers: []
      watchFiles: []
      debounceMs: 300
```

`providers` 是要保护的 provider ID 列表，空列表保护模型名含 `Claude` 的路由；这只是路由选择规则，不表示已经确认上游经过 Magpie。`watchFiles` 可添加其他配置文件的绝对路径。监听文件所在目录，因此原子替换配置文件后仍能继续监听；不递归监控磁盘。

服务端使用 DSH storage domain 保存会话 ID、路由、定义哈希及待处理状态。不会保存原始系统提示、工具参数、密钥或聊天正文；原始用户消息仍由宿主 inbox 保存。

## 边界

这是发生变更后、模型请求发出前的保护，不是插件卸载的全局否决器。变更已经发生，插件不会自动恢复原工具或原缓存；已经发出的请求无法撤回。

保护范围是实际注册通知、HMR、插件管理通知及配置文件变化。外部服务静默改变内容、没有通知也没有受监控文件变化的动态闭包、模型或路由切换、压缩和转发层改写历史、上游缓存过期不属于本插件的检测范围。

会话尚未加载时先保留待核对标记，恢复后才使用它自己的 scope 核对。已保存基准不会因 idle、关标签页或重启而自动视作接受；全新会话没有旧前缀，不阻塞首次请求。首次装插件无法追溯之前已经消费的重建。

检查期间定义持续变化、无法组装或无法保存接受记录时保留保护状态。接受本次变更不保证上游命中缓存，也不能把 token 数直接换算成订阅额度百分比。

使用 Node.js 24：

```bash
npm test

```

测试覆盖正常步骤零核对、工具与系统指令变化、content 块与字符串指纹一致、旧数组哈希治愈、纯 UI、事件合并、变更竞态、取消、恢复、消息保序、接受失败重试、状态读取排队和原子替换文件监听。另在开发宿主上核实了 SDK 模块导入。
